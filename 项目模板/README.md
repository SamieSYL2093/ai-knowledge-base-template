## 这是什么

所有项目的标准结构模板。新建项目时，直接复制这个目录的结构，保证所有项目长得一样。

---

## 标准目录结构

```
项目名/
├── 00_项目总览.md          ← 🚪 入口（必须）
├── _入项指引.md            ← 🆕 新AI入职指南（必须）
├── 01_XXX.md              ← 主题文档（按需编号）
├── 02_XXX.md
├── ...
├── 对话记录/               ← AI对话归档（必须，2-12规范）
│   ├── 01_raw/            # 原始HTML保真
│   ├── 02_text/           # 整理版Markdown
│   └── README.md          # 对话索引
├── images/                ← 截图存档（按需）
│   └── README.md
├── configs/               ← 配置文件（按需，脱敏）
├── scripts/               ← 实用脚本（按需）
├── .gitignore             ← Git忽略规则（必须）
└── README.md              ← 项目简介（给外人看的）
```

## 必须有的文件

| 文件/目录 | 为什么必须 |
|----------|-----------|
| `00_项目总览.md` | 项目入口，所有AI进来先读这个 |
| `_入项指引.md` | 新AI入职指南，统一入职流程 |
| `对话记录/` | 2-12规范，AI对话统一归档 |
| `.gitignore` | 避免把临时文件、大文件提交进Git |

## 核心协作文件（复制即用）

多AI协作只需 3 个核心文件，放在本模板根目录即可，直接复制套用（详见 `1-05_多AI协作规范.md`）：

| 文件 | 谁写 | 作用 |
|------|------|------|
| `想法池.md` | 你（AI 只读） | 灵感/需求随手记，不用整理格式 |
| `派活工单表.md` | AI 改，你看 | 工单对讲机，所有任务统一管 |
| `待决策.md` | AI 写，你看 | AI 卡住的事、要你拍板的事，统一通道 |

> 单AI用户也能直接用这三个文件管自己的任务和待办。

## 两层入职体系

```
新AI进来
    │
    ├─→ 第一层：全局接入指令（知识库）
    │      _入项指引.md（知识库根目录）
    │      → 体系架构、全局规则、记忆分层
    │
    └─→ 第二层：项目入项指引（本项目）
           _入项指引.md
           → 本项目特有规则、技术栈、协作规范
```

**分工明确**：
- 全局的放知识库，所有AI通用
- 项目特有的放项目里，各项目自己维护

## 新建项目SOP（7步）

1. 复制本模板目录，改名为项目名
2. 改 `00_项目总览.md` 里的项目信息
3. 改 `_入项指引.md` 里的项目特有内容
4. 在知识库 `3-01_项目与技能登记.md` 登记
5. `git init` 初始化仓库
6. 首次提交：`git add . && git commit -m "项目初始化"`
7. 通知其他AI：新项目建好了

## 模板版本检查机制

### 怎么知道项目模板是不是最新的？

1. **每个项目的00总览开头记录"模板版本"**（如v0.2）
2. **知识库的项目登记表里也记录每个项目的模板版本**
3. **AI进项目时**：对比项目的模板版本和本模板仓库的最新版本，如果有更新，提醒用户：
   - 小更新（格式优化、补充说明）：建议同步
   - 大更新（结构变更）：根据项目情况自行决定

### 版本号规则

- v0.x：初版迭代期，变化可能比较大
- v1.0：稳定版，之后只做小更新
- 大版本号变更：结构有重大调整
- 小版本号变更：格式优化、补充说明、小bug修复

## 模板更新说明

模板会随着体系完善持续更新。已有的项目可以选择是否同步新版模板：
- 小更新（格式优化、补充说明）：建议同步
- 大更新（结构变更）：根据项目情况自行决定
