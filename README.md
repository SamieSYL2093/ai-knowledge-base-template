## ✨ 为什么需要这个？

你是不是也遇到过这些问题：
- 😫 换个 AI 平台就要重新解释你是谁、做什么的、有什么规则
- 😫 刚在豆包调好的辅导计划格式，换 Kimi 又写跑偏了
- 😫 上次踩的坑（比如"VBS换行必须用 vbCrLf"），换个 AI 又踩一遍
- 😫 网页版 AI 读不了本地文件，每次都要手动复制粘贴一堆规范
- 😫 项目太多不知道哪个在哪个目录，每次派活都要翻半天

**这个模板就是解决这些问题的**：一套通用的文件规范，所有 AI 共用同一份记忆、同一份规则，换平台不换脑子。

## 🚶 小白三步上手（不用懂Git，不用懂技术）
就三步，3分钟就能用起来：
1. **拿下来**：点页面右上角绿色「Use this template」按钮创建你自己的仓库，或者直接下载ZIP解压到你电脑上
2. **改成你的**：打开 `1-01_用户档案.md`，把里面的示例换成你自己的信息——你是谁、做什么工作、有什么习惯和规矩
3. **发给AI**：把 `1-04_接入指令模板.md` 里的内容复制，发给你用的任何AI（豆包/Kimi/DeepSeek/Claude/OpenAI都可以），它自己会读完所有规则，按你的习惯干活
> 💡 没有AI也能用：它就是一堆整理好的规范文档模板，你自己用来整理项目、沉淀SOP、管理文件也完全好用。

## 📂 一图看懂：文件夹放哪 + 怎么用

<img src="p13-overview.svg" alt="知识库文件夹放哪：和你的项目们平行">

**两步上手：**

1. **文件夹放哪？** —— 和你的项目文件夹**平行**放。项目泛指一切需要用 AI 辅助干活的事：软件开发、教材课件、学习规划、数据分析、资料整理……这样知识库才能同时管所有项目
2. **让 AI 接入** —— 把知识库里的「入项指引」文件发给电脑端 AI（能读写本地文件的 AI），或者复制知识库文件夹路径给它，都一样。AI 秒懂知识库，你不懂的可以问 AI 了

> 规范文件是给 AI 读的，你不用全看。想扣细节往下翻「目录结构」。

## 🛡️ 内置防呆机制（踩了几十次坑总结的精华 · v1.1 7-31更新）

这些都是实际用多AI协作踩坑踩出来的规则，从根源上避免90%的常见问题：

| 防呆规则 | 解决什么坑 |
|---------|-----------|
| 📂 **项目入项强制阅读** | 每个项目根目录自带 `_入项指引.md`，新AI进项目必须先读这个再干活，不会再出现"不知道规则乱改文件" |
| 🗂️ **Git版本管理，禁止乱备份** | 所有文件靠Git做版本管理，**不需要单独备份文件**（禁止生成`xxx_v0备份`这种冗余文件），改坏了一行命令回滚，再也不会出现一堆备份文件分不清哪个是最新的 |
| 📄 **双版分离，禁止手改生成文件** | MD源文件给AI改，HTML/导出文件脚本自动生成，禁止手改生成文件——再也不会出现"手改的内容下次生成被覆盖" |
| 🎯 **一句话派活公式** | 派活只需要说：`打开项目\_入项指引.md，读完后做：xxx`，AI自动读所有规则，不用每次重复讲要求 |
| 🧠 **记忆分层铁律** | 重要信息必须写入文件，不能只存在AI脑子里——换AI、换平台不会丢记忆 |
| 🎯 **单一事实来源** | 同一条知识只在一个文件维护，其他地方只引用不复制——再也不会出现"同一个规则A文件改了B文件没改，AI看B文件做错" |
| ✍️ **改完立即提交署名** | 改完文件必须立即Git提交，带上AI平台名——谁改了什么、什么时候改的一目了然，出问题一秒回溯 |
| 📝 **文件头元信息强制** | 每个文件开头必须有「用途/关键词/更新日期」三行，AI一秒判断要不要读这个文件，不会读错、漏读 |
| ⚠️ **冲突不擅自改** | 遇到规则冲突、不确定的地方，AI不能自己改，必须先问你——不会出现AI自作主张改坏你的规范 |
| 🚫 **禁止重复记工作流** | Git就是唯一工作记录，不需要额外记日志、记改了什么——减少冗余工作 |
| 📻 **多AI协作对讲机协议** | 多AI同时干活不抢单、不覆盖、不冲突，工单状态机+追加制，8个AI同时写一张表也不会乱 |
| 🏷️ **三级验收防翻车** | L0免验（机械操作）/ L1抽查（内容产出）/ L2全验（高风险），级别在派单时写明，翻车自动升级 |
| 📝 **阴性结果留痕** | 审过没发现≠没审——每次验收必须留记录，防止"到底审了没有"扯皮 |

## ⚡ 3 分钟快速开始

### 1. 获取模板
```bash
# 方式一：Git 克隆（推荐，方便后续更新）
git clone https://github.com/SamieSYL2093/ai-knowledge-base-template.git
cd ai-knowledge-base-template

# 方式二：直接下载 ZIP 解压
```

### 2. 填写你的档案
打开 `1-01_用户档案.md`，把里面的占位符换成你自己的信息：
- 你是谁、做什么工作
- 你的偏好、工作习惯
- 常用工具、技术栈
- 你的规则、红线

这是所有 AI 的"入职档案"，填一次所有 AI 都能看到。

### 3. 测试第一个 AI
把 `1-04_接入指令模板.md` 的内容复制发给你常用的 AI（比如豆包/Kimi/DeepSeek），它会自动：
1. 读完所有规范
2. 记住你的档案和偏好
3. 按照你的规则开始干活

### 4. 开始使用
- 派活给 AI 时，先让它读对应项目的 `_入项指引.md`，再讲任务
- 踩了新坑就写到 `20-29_工具技能/` 里，所有 AI 以后都不会再踩
- 给网页版 AI 发内容时，用 `pack.py` 一键打包需要的文件：
```bash
python pack.py 00 01          # 合并用户档案+管理规范 → 直接粘贴给AI
python pack.py 00 02 你的文件  # 按需组合任意文件
```

- 🚀 **研发团队**：需求文档、设计决策、踩坑记录——这些"代码之外的东西"才是团队最贵的资产。代码有 Git 管，协作规则谁来管？P13 补的就是 Jira/飞书/Git 管不到的那块：**人跟人之间的隐性约定，显性化**

## 🎨 设计原则

1. **单一事实来源**：同一条知识只在一个文件里维护，不重复、不冲突
2. **AI 优先设计**：每个文件头部有标准元信息，AI 一秒判断该不该读、怎么读
3. **平台无关**：不绑定任何特定 AI 产品，豆包/Kimi/DeepSeek/Claude 都能用
4. **Git 友好**：纯文本 Markdown，Git 完美管理版本，谁改了什么一目了然
5. **最小可用**：不需要复杂部署，不需要数据库，克隆就能用，想扩展随时加

## ❓ 常见问题

**Q：我不会用 Git 能用吗？**
A：完全可以，直接下载 ZIP 解压就能用，Git 只是用来做版本管理，不用也没关系。

**Q：网页版 AI 读不了本地文件怎么办？**
A：用内置的 `pack.py` 一键打包你需要的文件，自动复制到剪贴板，直接粘贴给网页版 AI 就行。

**Q：只用网页版 AI（豆包网页版/Kimi网页版/ChatGPT）体验会打折扣吗？**
A：会。P13 的核心设计假设 AI 能读写本地文件——桌面端 AI（豆包桌面端/OpenClaw/Claude Code/WorkBuddy）是满血体验，AI 自动读文件、改文件、Git 提交一气呵成。网页版 AI 只能靠你手动粘贴文本中转，能用但效率打折。建议至少用一个桌面端 AI，其他辅助用网页版。

**Q：我已经有自己的文件结构了怎么办？**
A：模板只是参考，你可以完全按照自己的习惯改目录结构，只要遵守最基础的文件规范就行。

**Q：可以商用吗？**
A：完全可以，MIT 协议，随便用、随便改，只要保留原作者署名就行。

**Q：这到底是啥？**
A：一堆规范文件，你的规矩都写在里面，AI 读了就按你的规矩干活。看上面「一图看懂」就明白了。
